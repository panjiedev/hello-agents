# 04_sft_training.py 剥洋葱式讲解

> 源文件：`code/chapter11/04_sft_training.py`（326 行）
> 一句话概括：**监督微调（SFT）的完整配置手册——让模型逐 token 模仿人类写的解题过程，学会"先分步推理、再报 Final Answer"的规范格式。**

---

## 🧅 第一层（最外层）：这个文件在干什么？

SFT（Supervised Fine-Tuning，监督微调）是后训练的第一步，本质是**带答案的抄写练习**：把 `01_dataset_loading.py` 里的 SFT 格式数据（prompt + completion）喂给模型，用标准的交叉熵损失让模型学会"看到这样的题，就写出这样的解答"。

这个文件用 6 个示例从最小配置一路加码到全量训练，核心只有一个配置字典：

```python
config = {
    "action": "train",
    "algorithm": "sft",
    "model_name": "Qwen/Qwen3-0.6B",
    "output_dir": "./output/sft_minimal",
    "max_samples": 10,
    "num_epochs": 1,
}
```

示例 1（第 30-37 行）证明：跑通 SFT 最少只需 6 个字段。剩下 5 个示例都在回答"往这个字典里再加什么、为什么加"。

---

## 🧅 第二层：SFT 到底在训练什么？

配置很薄，底下的机制值得剥一层。SFT 的训练循环是经典的监督学习：

```
拼接 prompt + completion → 前向传播 → 对 completion 部分逐 token 算交叉熵 → 反向传播
```

三个要点：

1. **损失只算 completion 部分**——prompt 是"题目"，模型不需要学会复述题目，只需要学会接着题目往下写解答；
2. **每个 token 都有标准答案**——这是和 GRPO 最根本的区别：SFT 的监督信号密集到逐 token，模型全程"临摹字帖"，自己从不发挥；
3. **它学到的主要是"格式与套路"**——分步推理的行文模式、`Final Answer: X` 的收尾格式。至于推理是否真的正确，SFT 无法保证（临摹得再像，不代表会做新题）——这就是为什么后面还需要 GRPO。

对本章流水线而言，SFT 还有一个隐藏使命：**把输出格式钉死**。`02_reward_functions.py` 的答案提取依赖 `Final Answer:` 这类标记，SFT 先把格式教规范，GRPO 阶段的奖励信号才不会因为提取失败而充满噪声。

## 🧅 第三层：学习率的三档哲学（第 153-196 行）

示例 4 单独拿学习率开了一节，因为它是微调中最容易翻车的参数：

```python
learning_rates = {
    "保守 (1e-5)": 1e-5,   # 模型已经很好,只需微调
    "推荐 (5e-5)": 5e-5,   # 标准训练,推荐使用
    "激进 (1e-4)": 1e-4,   # 快速实验(可能不稳定)
}
```

为什么微调的学习率要比预训练小一个量级？因为基座模型的权重已经蕴含了海量预训练知识，**微调是"精修"不是"重塑"**——学习率太大，几步梯度就能把预训练学到的通用能力冲掉（灾难性遗忘）。`5e-5` 是 LoRA 微调的经验甜点：LoRA 参数是从零初始化的小矩阵，可以比全参微调略大胆一点，但也就到 1e-4 为止。

记住这个数字还有一个用意：**GRPO 篇会用 `1e-5`，比 SFT 再小 10 倍**——到时候对比着看，能直接读出两种训练范式的"胆量"差异。

## 🧅 洋葱心：显存优化的最后防线（第 214-230 行）

```python
config = {
    ...
    "batch_size": 1,   # 最小batch size
    "use_lora": True,
    "lora_r": 8,       # 使用较小的秩
    "lora_alpha": 16,
}
# 预计显存占用: ~3-4GB
```

示例 5 是"显卡不够大"时的求生配置，它展示了显存的三个可压缩维度，按优先级排列：

1. **`use_lora: True`**——最大头：冻结基座权重后，优化器状态（Adam 的动量和方差，通常是参数量的 2 倍大小）只需为 LoRA 小矩阵保留，一刀砍掉最肥的一块；
2. **`batch_size: 1`**——激活值显存与 batch 成正比，压到 1 是极限（代价是训练慢、梯度噪声大）；
3. **`lora_r: 8`**——最后一点边角料，从 16 降到 8 省一半 LoRA 参数。

3-4GB 意味着入门游戏卡就能微调 0.6B 模型——**"训练大模型"的门槛在 LoRA 时代真的降到了个人玩家水平**，这也是本章敢把训练作为教学内容的底气。

## 🎯 剥完之后：它在本章的位置

SFT 是"SFT → GRPO"两级火箭的第一级：

| 阶段 | 输入 | 学到什么 |
|---|---|---|
| **SFT（本文件）** | 人写的完整解答 | 输出格式、解题套路（模仿） |
| GRPO（05 篇） | 只有最终答案 + 奖励函数 | 推理的正确率（试错优化） |

`05_grpo_training.py` 第 179 行的 `"model_name": "./output/pipeline_sft"` 会直接把本文件的产物当作 GRPO 的起点。顺序不能颠倒：没有 SFT 打底，基座模型的输出格式千奇百怪，奖励函数提取不到答案，GRPO 的奖励信号几乎全是 0，训练根本无从"抓起"。**先模仿，再超越**——这正是 DeepSeek-R1 等推理模型验证过的后训练配方。
