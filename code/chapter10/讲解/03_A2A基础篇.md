# A2A 基础篇 剥洋葱式讲解

> 源文件：`code/chapter10/07_SimpleA2AAgent.py`（84 行）、`08_CustomA2AAgent.py`（47 行）、`09_A2A_Server.py`（49 行）、`09_A2A_Client.py`（21 行）、`09_A2A_Network.py`（92 行）、`09_A2A_WithAgent.py`（203 行）
> 一句话概括：**MCP 解决"智能体用工具"，A2A（Agent-to-Agent Protocol）解决"智能体找智能体"——把每个 Agent 变成带技能清单的 HTTP 服务，让协作从进程内的函数调用升级为跨网络的对等通信。**

---

## 🧅 第一层（最外层）：这组文件在干什么？

MCP 客户端篇的 `06_MultiAgentDocumentAssist.py` 里，两个 Agent 靠 f-string 拼接传话——它们必须活在同一个 Python 进程里。A2A 协议打破这个限制：**每个智能体是一个独立的 HTTP 服务，对外公布自己的名字、能力和技能；任何其他智能体拿着 URL 就能调用它的技能。**

六个文件分三步走：

| 文件 | 讲什么 |
|---|---|
| `07_SimpleA2AAgent.py` / `08_CustomA2AAgent.py` | 服务端概念：`A2AServer` + `@skill` 装饰器，先本地测试技能 |
| `09_A2A_Server.py` / `09_A2A_Client.py` | 真正跨进程：一边 `run()` 起服务，一边 `execute_skill()` 远程调用 |
| `09_A2A_Network.py` / `09_A2A_WithAgent.py` | 组网与集成：三个 Agent 流水线协作；把 A2A Agent 封装成 SimpleAgent 的工具 |

---

## 🧅 第二层：`07` 与 `08`——Agent 的"名片"和"技能"

创建一个 A2A 智能体（`07_SimpleA2AAgent.py` 第 12-20 行）：

```python
calculator = A2AServer(
    name="calculator-agent",
    description="专业的数学计算智能体",
    version="1.0.0",
    capabilities={
        "math": ["addition", "subtraction", "multiplication", "division"],
        "advanced": ["power", "sqrt", "factorial"]
    }
)
```

这四个参数不是随便填的元数据——它们构成 A2A 协议里的 **Agent Card（智能体名片）**：名字、简介、版本、能力清单。别的智能体访问这个服务时，先读名片再决定要不要合作，这是 A2A "发现"机制的基础。

技能的注册方式和 MCP 服务端如出一辙（第 23-36 行）：

```python
@calculator.skill("add")
def add_numbers(query: str) -> str:
    """加法计算"""
    parts = query.replace("计算", "").replace("加", "+")
    if "+" in parts:
        numbers = [float(x.strip()) for x in parts.split("+")]
        return f"计算结果: {' + '.join(map(str, numbers))} = {sum(numbers)}"
```

但注意签名的差别：MCP 工具是 `add(a: float, b: float)`——结构化参数；A2A 技能是 `add_numbers(query: str)`——**一段自然语言文本**。技能函数要自己解析"计算 10 + 5"这样的输入。这是两个协议定位不同的直接体现：MCP 面向程序调用（参数严格），A2A 面向智能体对话（消息宽松）。

文件末尾的测试（第 73-81 行）直接从 `calc_agent.skills["add"](query)` 字典里取函数本地调用——**还没有任何网络**，先验证技能逻辑本身。`08_CustomA2AAgent.py` 是同一模式的极简复刻（greet + calculate 两个技能，其中 calculate 用白名单字符过滤后才 `eval`，第 27-30 行），确认"创建 → 注册技能 → 本地测试"这条路你能自己走一遍。

另外两个文件开头都有 `A2A_AVAILABLE` 检查（`07` 第 5-7 行）——A2A 依赖可选包 `a2a-sdk`，没装就友好提示而不是抛 ImportError，这是可选依赖的标准处理姿势。

## 🧅 第三层：`09_A2A_Server.py` + `09_A2A_Client.py`——跨进程的第一次握手

现在把技能真正发布到网络上。服务端（`09_A2A_Server.py` 第 11-35 行）：

```python
researcher = A2AServer(name="researcher", description="负责搜索和分析资料的Agent", version="1.0.0")

@researcher.skill("research")
def handle_research(text: str) -> str:
    match = re.search(r'research\s+(.+)', text, re.IGNORECASE)
    topic = match.group(1).strip() if match else text
    result = {"topic": topic, "findings": f"关于{topic}的研究结果...", "sources": [...]}
    return str(result)

def start_server():
    researcher.run(host="localhost", port=5000)
```

`researcher.run(host, port)` 一行，Agent 就变成了监听 5000 端口的 HTTP 服务。主线程用 `threading.Thread(daemon=True)` 把它放到后台，再用 `while True: sleep(1)` 挂住进程（第 38-48 行）——教学代码里常见的"简易服务托管"。

客户端是**另一个独立进程**（`09_A2A_Client.py` 第 13-17 行）：

```python
client = A2AClient("http://localhost:5000")

response = client.execute_skill("research", "research AI在医疗领域的应用")
print(f"收到响应：{response.get('result')}")
```

这三行就是 A2A 调用的全部形态：**URL 定位智能体，技能名 + 文本消息发起请求，返回一个含 `result` 的字典**（出错时含 `status`/`error` 字段，`09_A2A_WithAgent.py` 第 107-110 行可见完整判断）。对比 MCP 的 `call_tool("read_file", {"path": ...})`——A2A 传的是句子，MCP 传的是表单。

还有个不起眼但重要的细节：技能内部用正则 `research\s+(.+)` 从消息里剥出主题（第 22-23 行）。**消息格式约定（"技能名 + 空格 + 内容"）是调用双方的隐性协议**——第四章"提示词定协议，代码做解析"的铁律，在 Agent 间通信里换了个舞台重演。

## 🧅 第四层：`09_A2A_Network.py`——三个 Agent 组成流水线

一对一通了，就能组网。这个文件在**同一脚本里起三个服务**：researcher（5000 端口）、writer（5001）、editor（5002），各注册一个技能（第 11-61 行），然后（第 64-72 行）：

```python
threading.Thread(target=lambda: researcher.run(port=5000), daemon=True).start()
threading.Thread(target=lambda: writer.run(port=5001), daemon=True).start()
threading.Thread(target=lambda: editor.run(port=5002), daemon=True).start()
time.sleep(2)  # 等待服务启动

researcher_client = A2AClient("http://localhost:5000")
writer_client = A2AClient("http://localhost:5001")
editor_client = A2AClient("http://localhost:5002")
```

协作流程是一条清晰的接力（第 75-86 行）：

```python
def create_content(topic):
    research = researcher_client.execute_skill("research", f"research {topic}")
    research_data = research.get('result', '')

    article = writer_client.execute_skill("write", f"write {research_data}")
    article_content = article.get('result', '')

    final = editor_client.execute_skill("edit", f"edit {article_content}")
    return final.get('result', '')
```

与 MCP 篇 `06` 的 f-string 接力对比：形式几乎一样（上游输出塞进下游输入），但**每一棒都跨越了 HTTP 边界**——三个 Agent 可以随时拆到三台机器上，`create_content` 一个字不用改，只需换 URL。这就是"协议化协作"相对"进程内协作"的本质增益。

代价也诚实地暴露着：writer 收到的是 `str(dict)` 再 `eval` 回来（第 36-41 行），消息一旦不合格式就落入 except 分支。教学代码用 eval 图省事，生产环境应换成 JSON——这正说明了**统一消息 schema** 的价值。

## 🧅 洋葱心：`09_A2A_WithAgent.py` 的 A2ATool 封装（第 73-110 行）

前面所有调用都是硬编码的"人类编排"。最后一块拼图：让 **LLM 自己决定问哪个远程 Agent**。做法是把 A2A 客户端包装成 HelloAgents 的 `Tool`：

```python
class A2ATool(Tool):
    """将 A2A Agent 封装为 HelloAgents Tool"""

    def __init__(self, name: str, description: str, agent_url: str, skill_name: str = "answer"):
        self.client = A2AClient(agent_url)
        self._parameters = [ToolParameter(name="question", type="string",
                                          description="要问的问题", required=True)]

    def run(self, **kwargs) -> str:
        question = kwargs.get('question', '')
        result = self.client.execute_skill(self.skill_name, f"answer {question}")
        if result.get('status') == 'success':
            return result.get('result', 'No response')
        else:
            return f"Error: {result.get('error', 'Unknown error')}"
```

这个类是**两个世界的翻译官**：

- 对内（SimpleAgent 侧）：它是一个标准 Tool——有 `name`、`description`、`ToolParameter`，LLM 在工具清单里看到"tech_expert: 技术专家，回答技术相关问题"就知道什么时候用它；
- 对外（A2A 侧）：`run()` 把 LLM 给的 `question` 拼成 `"answer {question}"` 格式的消息，`execute_skill` 发给远程 Agent，再把 `result` 字典拆包成纯字符串还给 LLM。

装配之后（第 137-154 行），接待员 SimpleAgent 面对"你们的产品有什么优惠活动吗？"会自己路由给销售顾问（6001 端口），面对"如何配置 SSL 证书？"会路由给技术专家（6000 端口）——**远程智能体在 LLM 眼里和一个计算器工具没有任何区别**。这行等式是 A2A 基础篇的终点：

> 远程 Agent ≈ 一个会说话的工具。

## 🎯 剥完之后：它在本章的位置

A2A 基础篇回答的问题是：**独立进化的智能体之间怎么互相调用？**答案是"名片 + 技能 + HTTP"：Agent Card 让你被发现，`@skill` 让你可被调用，`A2AClient` 让你调用别人。

| 概念 | MCP | A2A |
|---|---|---|
| 通信双方 | 智能体 ↔ 工具服务 | 智能体 ↔ 智能体 |
| 消息形态 | 结构化参数（JSON Schema） | 自然语言文本（技能自己解析） |
| 发现机制 | `list_tools` | Agent Card（name/description/capabilities） |
| 典型调用 | `call_tool("add", {"a":10,"b":20})` | `execute_skill("research", "research 某主题")` |

A2A 应用篇会用官方 `A2ATool`（不用再手写翻译官）搭出智能客服和 Agent 协商；而"网络里 Agent 多到客户端记不住 URL"的那一天，就轮到 ANP 篇的服务发现登场了。
