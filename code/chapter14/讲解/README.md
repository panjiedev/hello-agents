# Chapter 14 代码剥洋葱讲解

对 `code/chapter14/helloagents-deepresearch/` 综合项目的逐层拆解。这是一个前后端全栈的 **DeepResearch 深度研究智能体**：用户提交一个研究主题，后端把它拆成待办任务、并发联网检索、逐任务总结沉淀为笔记、最终汇总成结构化报告，全过程以事件流实时推送到浏览器。每篇文档都采用"剥洋葱"结构：从最外层的**这个文件在干什么**开始，一层层剥到最核心的**那几行关键代码**，最后回到全局，说明它在整个项目中的位置。

## 一条主线

本章主线：**DeepResearch 深度研究智能体——规划、搜索、笔记、报告的闭环**。一次研究从提问到报告，走的是这样一台状态机：

> **规划**（planner 把主题拆成 3~5 条带 query 的 TodoItem）
> **搜索**（每个任务并发联网，材料整理成"给人看的引用 + 给模型吃的上下文"）
> **笔记**（总结专家先读后写，notes/ 目录充当跨 Agent 的中间记忆）
> **报告**（reporter 摊开全部任务战果 + 读回笔记，产出五段式报告并落盘）

而这一切对用户不是黑盒：每个任务状态翻牌、每段总结 chunk、每次笔记读写，都被包成事件顺着 SSE 推到浏览器——**后端定事件协议，前端做投影**。

贯穿五篇的两条工程线索：

1. **chapter4 那条铁律的放大版**——"提示词定协议，代码做解析"：规划 JSON 有三层解析瀑布兜底，`[TOOL_CALL:note:{...}]` 有正则收线，`tags` 里的 `task_N` 是提示词埋钩、代码收线的接头暗号；协议一路放大到前后端之间，就成了 SSE 事件流。
2. **为不可靠的 LLM 铺安全网**——规划失败有 fallback task，搜索失败有 skipped 状态，`<think>` 有流式剥除，报告笔记有"先查再更新、失败再新建"；智能体工程的一半代码，都花在接住模型的每一种失手上。

> 前置阅读：chapter4 的讲解（`code/chapter4/讲解/`）介绍了 ReAct / Plan-and-Solve / Reflection 三种范式——本章可视为 Plan-and-Solve 的工程化终极形态：计划变成结构化任务、执行变成并发流水线、中间结果外置为笔记、全过程变成可观测的事件流。
