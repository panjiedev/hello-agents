# 01_basic_agent_example.py 剥洋葱式讲解

> 源文件：`code/chapter12/01_basic_agent_example.py`（38 行）
> 一句话概括：**用 30 行搭一个会搜索的智能体，然后问出全章的灵魂拷问——它到底表现如何？我们凭什么说它"好"？**

---

## 🧅 第一层（最外层）：这个文件在干什么？

这是本章唯一一个**不做评估**的文件。它构建了一个再普通不过的智能体：一个 LLM、一段系统提示词、一个搜索工具，然后问它"最新的 AI 技术发展趋势是什么？"。

运行它，你会得到一段看起来头头是道的回答。然后呢？

- 它的回答**对不对**？搜索结果是三天前的还是三年前的？
- 它**该搜索时搜了吗**？还是凭训练记忆瞎编？
- 换个模型、改句提示词，它是**变强了还是变弱了**？

凭肉眼一条条看回答，既不客观也不可规模化。这个文件的全部使命，就是把这个问题摆在你面前——**它是本章后面所有评估代码的"被测对象"原型**。

---

## 🧅 第二层：系统提示词——又见"协议"（第 17-26 行）

```python
system_prompt = """你是一个AI助手，可以使用搜索工具来获取最新信息。

当需要搜索信息时，请使用以下格式：
[TOOL_CALL:search:搜索关键词]
```

熟悉的配方：**提示词定协议，代码做解析**（chapter4 讲解里反复出现的工程铁律）。`[TOOL_CALL:search:...]` 就是智能体和框架之间约定的暗号——LLM 输出这个格式，框架就拦截下来真的去执行搜索。

但注意一个微妙的问题：提示词说"请在回答问题前先使用搜索工具"，这只是一个**请求**，不是**保证**。LLM 完全可能不听话、直接作答。它听没听话、格式写没写对——恰恰就是 BFCL 这类"函数调用基准"要量化的东西（见 `bfcl_evaluation.md`）。

---

## 🧅 洋葱心：三行装配（第 28-36 行）

```python
agent = SimpleAgent(name="AI助手", llm=llm, system_prompt=system_prompt)
agent.add_tool(SearchTool())
response = agent.run("最新的AI技术发展趋势是什么？")
```

脑（`llm`）、性格（`system_prompt`）、手（`SearchTool`），三行组装完毕，一行运行。这套 `SimpleAgent + HelloAgentsLLM` 的组合会贯穿全章：后面每一个评估脚本，测的都是这样组装出来的智能体——评估工具改变的从来不是智能体本身，而是**喂给它的题目和给它打分的规则**。

## 🎯 剥完之后：它在本章的位置

这个文件是全章的"第 0 页"：先给你一个能跑的智能体，再让你意识到"能跑"和"跑得好"之间隔着一整套评估体系。本章剩下的内容就是回答那三个拷问：

| 拷问 | 对应基准 | 对应文档 |

| 工具调用写对了吗？ | BFCL（AST 匹配） | `bfcl_evaluation.md` |
| 真实世界任务答对了吗？ | GAIA（准精确匹配） | `gaia_evaluation.md` |
| 没有标准答案时怎么评？ | LLM Judge / Win Rate | `data_generation_metrics.md` |
