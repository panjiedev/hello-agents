# HelloAgent_fastgptCase.json 剥洋葱式讲解

> 源文件：`code/chapter5/HelloAgent_fastgptCase.json`（约 790 KB，单行压缩 JSON；顶层三个键：`nodes`（37 个节点）、`edges`、`chatConfig`）
> 一句话概括：**一个 FastGPT"智能投顾小助手"——四路意图分发，王牌是"资产评估"分支：表单收集画像 → 风险评估 → 技术面/基本面/舆情面三位分析师接力 → 投资建议整合 → 生成可下载报告，是本章唯一的"多专家流水线"。**

---

## 🧅 第一层（最外层）：这个文件在干什么？

这个 JSON 大到无法通读（大部分体积是 toolSet 节点的工具 schema 声明），但 `chatConfig.welcomeText` 一段就把产品说明书写完了：

```
### 您好，我是智能投顾小助手！
1. 精通金融、投资理论...支持下载文档进行学习。
2. 提供实时市场新闻及数据...支持下载音频进行收听。
3. 能够根据填写的内容进行用户的风险画像评估，然后从当下的市场技术面、
   国情基本面、新闻媒体面三个方面进行专业的数据分析，最后推荐适合的资产投资方案。

[进行资产评估获取投资意见]
[查询现在贵州茅台的股价信息]
[市盈率和市净率有什么区别]
```

末尾三个方括号是可点击的引导问题，分别精准命中三条业务分支。**读 FastGPT 导出文件的顺序建议：chatConfig（产品皮）→ edges（骨架）→ 逐个 node 的 inputs（血肉）。**

## 🧅 第二层：问题分类 → 四条业务线

入口链路：`workflowStart (448745)` → `classifyQuestion (qwF019AgyYrZUOmh, 问题分类)`。分类节点的 `agents` 字段定义了四个出口（每个出口对应 edges 里一个 `sourceHandle`）：

| 出口 key | 分类描述 | 去向 |
|---|---|---|
| wqre | 用户资产风险画像评估，进行资产配置 | **资产评估流水线**（第四层细讲） |
| sdfa | 市场情报，每日市场新闻，获取音频 | 市场新闻情报专员 → 音频输出 |
| agex | 进行投资知识的教育，了解投资基础知识，查询资料 | 投资知识教育专员 → 学习文档 |
| x0PVwAxTQ0Dv9BST | 其他 | 通用咨询专员（兜底闲聊） |

和 Dify 的问题分类器一模一样的思想，只是这里的"类"少而精——四条都是完整的**业务线**而非单一功能。

## 🧅 第三层：FastGPT 的节点类型学——先认清五种积木

37 个节点看似庞杂，按 `flowNodeType` 归类只有五种主力积木：

- **`chatNode`**：纯对话节点，一段系统提示词 + 一个模型，不带工具。如 `风险评估分析师`、`通用咨询专员`；
- **`tools`**：**智能体节点**，带系统提示词且能自主调用工具。如四位分析师、两位专员；
- **`toolSet` / `pluginModule`**：工具供给节点，本身不在数据主线上，通过 `sourceHandle: "selectedTools"` 的边挂到某个 `tools` 节点上。本例挂了一堆狠货：`中国股票 MCP`、`且慢基金mcp`、`中文趋势聚合新闻`、`minimax-MCP`（语音合成）、`BI图表-蚂蚁版`、五个 `秘塔AI搜索`；
- **`formInput` / `textEditor` / `tool` / `answerNode` / `datasetSearchNode`**：确定性节点——表单、字符串拼接、Markdown 转文件、指定回复、知识库检索。

edges 里因此有**两种性质完全不同的边**：普通边（`xxx-source-right`，数据接力）和工具边（`selectedTools`，能力挂载）。这与 n8n 的 `main` / `ai_tool` 双轨制殊途同归——**"数据流"与"能力装配"分离，是所有平台表达 Agent 的共同选择**。

一个值得注意的量化事实：本例的工具边多达 15 条——比如 `投资知识教育专员 (bxA2VoAQoA9OrHyI)` 一个节点就挂了 BI 图表、秘塔搜索、中国股票 MCP、且慢基金 mcp、知识库搜索五件工具，其提示词里还专门写了一句非常"人间真实"的强调：

```
- 知识库搜索：特别还要必须调用知识库搜索，搜索有没有相关内容！！！
```

三个感叹号——**当模型总是"忘记"调某个工具时，提示词工程师的最后手段**。

## 🧅 第四层：王牌分支——五位专家的报告接力

"资产评估"分支是全图精华，一条笔直的流水线：

```
表单输入 → 风险评估分析师 → 市场技术面分析师 → 基本面分析师
        → 新闻社媒分析师 → 投资建议 → 文件生成 → 指定回复
```

**第一棒：`formInput` 表单输入（ensWNEXpaKDPmGDl）。** 五个下拉框：年龄、投资经验、月收入水平、能承受的最大亏损、投资目标。风险画像这种"必须凑齐五个字段"的输入，让用户自由打字反而低效——**表单是比对话更好的收集器**，这是低代码平台相对纯 LLM 应用的独有武器。

**第二棒：`风险评估分析师`（chatNode，glm-4.5）。** 它的 `userChatInput` 展示了 FastGPT 的变量语法 `{{$节点id.字段$}}`：

```
年龄：{{$ensWNEXpaKDPmGDl.年龄$}}
投资经验：{{$ensWNEXpaKDPmGDl.投资经验$}}
...
```

系统提示词是标准五段式（角色人设/背景/任务目标/限制提示/输出格式要求），要求输出"风险等级评估 + 评估理由 + 风险提示"，并明令禁止推荐具体产品、禁止保证收益。

**第三到五棒：三位 `tools` 分析师。** 各自的人设、模型、工具都不同——这是"按任务挑模型+挑工具"的集中展示：

| 分析师 | 模型 | 挂载工具 | 提示词亮点 |
|---|---|---|---|
| 市场技术面分析师 | doubao-seed-2-0-pro-**thinking** | 中国股票 MCP、秘塔搜索 | 精通 MACD/KDJ/RSI，强调 A 股涨跌停、T+1 特色 |
| 基本面分析师 | glm-4.5 | 中国股票 MCP、秘塔搜索 | ROE/PE/PB 筛选维度 + 价值/成长/主题/周期四策略 |
| 新闻社媒分析师 | glm-4.5 | 中文趋势聚合新闻、秘塔搜索 | 盯雪球/东财股吧/微博大 V；**必须输出情绪指数评分（1-10 分）**，且"不允许回复'无法评估情绪影响'" |

它们通过普通边**串行**执行，前一位的分析结果自然进入后一位的上下文——对照 chapter4：这就是把 Plan-and-Solve 的"Executor 逐步执行、历史递给下一步"画在了画布上。

**第六棒：`投资建议`（tools，Doubao-Seed-1.6 + BI 图表工具）。** 提示词开宗明义："用户已提供以下四份独立报告：用户风险评估结果 / 市场技术面分析 / 基本面分析 / 新闻社媒分析"——它是**汇总者**，负责整合四份报告、给出股/债/黄金配置比例、生成再平衡提醒表格，还可调 BI 工具把关键数据画成图。

**第七棒：`文件生成`（tool，markdownTransform）+ `指定回复`。** 把最终报告转成文件，回复只有一行：

```
[智能投顾报告]({{$fLWA2WGk2lCKYXzh.url$}})
```

用户点开就是一份可下载的完整投顾报告。

## 🧅 第五层：另外两条分支的"多模态交付"

**市场情报分支**：`市场新闻情报专员`（doubao，挂新闻聚合 + 秘塔搜索 + 股票/基金 MCP）产出简报后，接的不是回复节点，而是 `音频输出`（tools）——系统提示词只有一件事：

```
调用minimax-mcp的文本转语音功能将输入的简报转成音频输出：
-只输出[点击直接播放](<音频链接>)
```

**新闻不光能读，还能听**——TTS 通过 MCP 挂进来，与查股价的 MCP 在机制上没有任何区别。

**投资教育分支**：`投资知识教育专员` 答疑后，`文本拼接`（textEditor）把问答对排版成 `用户问题：... AI回复：...`，再经 `Markdown 转文件#2` 生成 `[投资学习文档](url)`。三条分支的交付物各不相同：**报告文件、音频、学习文档**——低代码工作流让"回答"升级成了"交付"。

## 🧅 洋葱心：datasetSearchNode——全场唯一的知识库节点

`知识库搜索`（ejTR7x9hn2vZwfHu，type: `datasetSearchNode`）以 `selectedTools` 边挂在投资教育专员身上，检索输入绑定 `{{$448745.userChatInput$}}`（用户原话），并开启了 `datasetSearchUsingExtensionQuery: true`（检索前先用 LLM 改写问题）。

它值得当"洋葱心"，是因为四个平台对 RAG 的处理在此完成了三重对照：

- n8n：向量库 `retrieve-as-tool` 包装成工具；
- FastGPT：知识库是**平台一等公民**（独立节点类型 + 后台可视化管理数据集），同样作为工具挂给 Agent；
- Dify / Coze 本例：干脆没用 RAG，靠 MCP 和插件实时取数。

**知识是"预先存好的"还是"实时查来的"，决定了整张图的形状。**

## 🎯 剥完之后：它在本章的位置

FastGPT 案例是本章复杂度的顶点——它回答的问题是：**一个专业领域的严肃业务（投顾），如何用工作流拆成多专家协作？**

| 对比维度 | FastGPT 本例 | 其他三例 |
|---|---|---|
| 分支内部结构 | 专家**串行流水线**（报告接力） | Dify 分支是单节点直达；Coze 无分支；n8n 单 Agent |
| 输入收集 | 表单节点（5 个下拉框） | 其余三例都是自由文本 |
| 交付形态 | 文件 / 音频 / 文档链接 | 其余基本是文本（Dify 另有图片/视频文件） |
| 工具生态 | MCP + 系统插件 + 知识库三管齐下 | n8n 靠 LangChain 生态；Dify 靠插件市场 + MCP |
| 数据引用 | `{{$节点id.字段$}}` | Dify `{{#节点id.字段#}}`，Coze `ref_node`，语法异形、思想同源 |

对照 chapter4 收尾：风险评估→三面分析→投资建议，本质是 **Plan-and-Solve 的静态化**（计划不再由 LLM 现场生成，而是产品经理画死在图上）；每位分析师"必须输出 X 格式"的提示词，仍是那条铁律——**提示词定协议，下游做解析**，只不过"下游"从解析代码换成了下一个节点。
