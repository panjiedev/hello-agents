# Word_Embedding.py 剥洋葱式讲解

> 源文件：`code/chapter3/Word_Embedding.py`（23 行）
> 一句话概括：**用一个 4 词、二维的迷你词向量空间，复现 NLP 史上最著名的等式：king − man + woman ≈ queen。**

---

## 🧅 第一层（最外层）：这个文件在干什么？

`N_gram.py` 把词当成**离散符号**——"king" 和 "queen" 在它眼里就像 ID 号 3 和 7，毫无关联。词嵌入（Word Embedding）的革命在于：**把每个词表示成一个连续的数字向量，让"语义相近"变成"向量距离近"，让"语义关系"变成"向量运算"。**

这个脚本手工构造了 4 个二维词向量，验证经典的"词向量代数"：

```
king − man + woman ≈ queen
（国王 − 男人 + 女人 ≈ 女王）
```

运行后会打印结果向量 `[0.9, 0.2]`，以及它与 "queen" 的余弦相似度 **1.0000**——完全同向。

---

## 🧅 第二层：这 4 个向量是精心设计的

```python
embeddings = {
    "king":  np.array([0.9, 0.8]),
    "queen": np.array([0.9, 0.2]),
    "man":   np.array([0.7, 0.9]),
    "woman": np.array([0.7, 0.3])
}
```

剥开这组数字，会发现两个维度各有隐含的"语义"：

| 词 | 第 1 维（可理解为"王权"） | 第 2 维（可理解为"男性度"） |
|---|---|---|
| king  | 0.9（高） | 0.8（高） |
| queen | 0.9（高） | 0.2（低） |
| man   | 0.7（低） | 0.9（高） |
| woman | 0.7（低） | 0.3（低） |

于是关系变成了几何：

- `king − man`：王权差 +0.2，男性度差 −0.1 → 这个差向量约等于"**平民 → 王室**"的方向；
- `queen − woman`：+0.2 和 −0.1 → **同一个方向**！

"性别"和"王权"这两种语义关系，在向量空间里各自对应一个**平移方向**。真实的 Word2Vec / GloVe 是在几百维空间中从海量语料**自动学出**这种结构，本脚本只是把它二维化、手工化，让你能一眼看穿。

---

## 🧅 第三层：向量运算与余弦相似度

### 类比运算（第 17 行）

```python
result_vec = embeddings["king"] - embeddings["man"] + embeddings["woman"]
#           [0.9, 0.8] - [0.7, 0.9] + [0.7, 0.3] = [0.9, 0.2]
```

直译："从 king 身上去掉'男人'的成分，再加上'女人'的成分"。落点 `[0.9, 0.2]` 恰好就是 queen 的坐标。

### 余弦相似度（第 11-14 行）

```python
def cosine_similarity(vec1, vec2):
    dot_product = np.dot(vec1, vec2)
    norm_product = np.linalg.norm(vec1) * np.linalg.norm(vec2)
    return dot_product / norm_product
```

数学形式：cos(θ) = (A·B) / (‖A‖ × ‖B‖)，即两向量夹角的余弦：

- **1** = 方向完全相同；**0** = 垂直（不相关）；**−1** = 方向相反。

---

## 🧅 第四层（洋葱心）：为什么用"夹角"而不用"距离"？

这是词嵌入领域一个真正重要的设计决策，值得剥到底：

1. **模长会被词频污染**。在真实训练中，高频词的向量往往模长更大，但"出现得多"不等于"语义不同"。余弦相似度只看**方向**，天然免疫模长干扰。
2. **高维空间中欧氏距离会失效**（维度灾难）：几百维里所有点对的距离趋于相近，区分度差；夹角仍然可判别。
3. 本例中 `result_vec = [0.9, 0.2]` 与 `queen = [0.9, 0.2]` 完全重合，所以相似度是满分 1.0。真实模型中通常得到 0.7~0.8 之间的值，且 queen 是全词表中最近的词——这正是 2013 年 Word2Vec 论文轰动一时的实验。

## 🎯 剥完之后：它在整个技术演进中的位置

| 阶段 | 词的表示 | 局限 |
|---|---|---|
| N-gram（`N_gram.py`） | 离散符号，靠计数 | 词与词之间零关联 |
| **词嵌入（本文件）** | **静态向量，语义可计算** | 一词一向量："苹果手机"和"吃苹果"里的"苹果"是同一个向量 |
| Transformer（`Transformer.py`） | 动态上下文向量 | ——由注意力机制根据上下文实时计算 |

词嵌入解决了"词义无法计算"的问题，但解决不了**一词多义**。这个缺口，正是下一个文件 `Transformer.py` 中自注意力机制登场的理由。另外注意：Transformer 里的 `nn.Embedding` 层，本质上就是本文件这个 `embeddings` 字典的可训练版本——一张"词 ID → 向量"的查询表。
